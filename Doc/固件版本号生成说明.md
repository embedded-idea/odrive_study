# 固件版本号生成说明

> 版本号不是手写在代码里的，而是**编译时从 git 标签自动生成**：`make` 调用 `tools/odrive/version.py`，把 git 状态转成 4 个 C 常量编进固件，再经 Fibre 接口暴露给上位机。本文说明整条链路、各层获取方式与踩坑记录。

## 1. 全链路一图流

```
git tag fw-v0.5.6                      ← 版本号的唯一事实来源(必须含小写 "fw")
    │
    │  make → AUTOHEADERS 伪目标(每次构建必跑)        Makefile L300~308
    │  python3 tools/odrive/version.py --output autogen/version.c
    ▼
autogen/version.c                      ← 4 个全局常量,每次构建重新生成
    │  编译进固件(C_SOURCES)                            Makefile L127
    ▼
MotorControl/odrive_main.h
    ├─ L160~163: extern const unsigned char fw_version_major_; ...
    └─ L215:     ODrive 类成员 fw_version_major_ = ::fw_version_major_;
    │
    │  odrive-interface.yaml L109~112: fw_version_*: readonly uint8
    │  Fibre 接口代码生成
    ▼
autogen/endpoints.hpp                  ← 端点 ID 9~12 挂到这 4 个成员
    ▼
上位机读取: odrivetool / OdrvStudio
```

## 2. version.py 做了什么

文件：`tools/odrive/version.py`（99 行），核心三步：

**① 取 git 描述**

```bash
git describe --always --tags --match='*fw*' --dirty='*'
```

- `--match='*fw*'`：只认名字含 `fw` 的 tag（**区分大小写**，tag 必须小写 `fw-` 开头）
- `--dirty='*'`：工作区有未提交改动时在末尾追加 `*`

**② 正则解析**

```python
regex = r'.*v([0-9]+)\.([0-9]+)\.([0-9]+)(.*)'
# "fw-v0.5.6-6-g696fea6" → (0, 5, 6, "-6-g696fea6")
# "fw-v0.5.6"            → (0, 5, 6, "")
```

第 4 组（后缀）非空 → `unreleased = True`。注意：后缀的内容（提交数、哈希、`*`）**被丢弃**，只判断有无。

**③ 输出 C 常量**

```c
const unsigned char fw_version_major_ = 0;
const unsigned char fw_version_minor_ = 5;
const unsigned char fw_version_revision_ = 6;
const unsigned char fw_version_unreleased_ = 1;
```

## 3. 版本号取值规则（git describe 语法）

```
fw-v0.5.6 - 6 - g696fea6 *
    │      │    │         │
  tag名  提交数 g前缀+HEAD短哈希  dirty标记(有未提交改动时)
```

| 构建时的 git 状态 | describe 输出 | 固件里显示 |
| --- | --- | --- |
| HEAD 正好在 `fw-vX.Y.Z` tag 上，工作区干净 | `fw-v0.5.6` | 0.5.6（正式版，unreleased=0） |
| tag 之后有 N 个提交 | `fw-v0.5.6-N-g<hash>` | 0.5.6**-dev**（unreleased=1） |
| 工作区有未提交改动 | 末尾追加 `*` | 0.5.6-dev |
| 无匹配 tag / 不在 git 仓库 | `[unknown version]` | 0.0.0-dev |

- `-N` 的 N = `git rev-list --count fw-v0.5.6..HEAD`：从 HEAD 往回数、经过几个提交才到 tag
- `g` 是 git 的标记前缀，用于区分后面的短哈希
- AUTOHEADERS 无条件执行，所以**同一份源码在不同 git 状态下编译，产出的版本号不同**——版本号是"构建时属性"而非"源码属性"

## 4. 各层怎么读版本号

| 层 | 方式 |
| --- | --- |
| 构建机（不接硬件） | `python3 tools/odrive/version.py`（打印版本 + C 代码） |
| 只要版本字符串 | `python3 -c "import sys; sys.path.insert(0,'tools/odrive'); import version; print(version.get_version_str())"` |
| 编译产物 | 看 `autogen/version.c` 文本 |
| 固件 C 代码 | 全局常量 `fw_version_major_` 等（`odrive_main.h` L160 extern），或 ODrive 类成员 `odrv->fw_version_major_` |
| odrivetool | `odrv0.fw_version_major / fw_version_minor / fw_version_revision / fw_version_unreleased`（属性名**不带**下划线） |
| OdrvStudio | 状态栏自动显示"固件 vX.Y.Z"（`core/worker.py` 轮询 + `gui/main_window.py` 拼接） |
| CAN 总线 | ❌ 0.5.x CANSimple 无版本消息，CAN 上读不到，需走 USB/UART（Fibre） |

odrivetool 拼接示例：

```python
>>> "%d.%d.%d%s" % (odrv0.fw_version_major, odrv0.fw_version_minor,
...                 odrv0.fw_version_revision,
...                 "-dev" if odrv0.fw_version_unreleased else "")
'0.5.6-dev'
```

上位机侧这 4 个属性就是 `autogen/endpoints.hpp` 里的 JSON 名（`fw_version_major`，ID 9~12）；刷机流程（`dfu.py`）在下载前正是用它们与本地固件比较新旧。

## 5. 发布正式版的操作

```bash
# 1. 确认工作区干净、HEAD 就是想发布的 commit
git status

# 2. 打小写附注 tag（必须 fw- 开头，version.py 只认 *fw*）
git tag -a fw-v0.5.7 -m "ODrive firmware v0.5.7"

# 3. 重新编译 → describe 输出裸 tag → unreleased=0
make clean && make -j$(nproc)

# 4. 验证
python3 tools/odrive/version.py
# Firmware version 0.5.7 (fw-v0.5.7)
```

推送到远程：`git push origin fw-v0.5.7`。

## 6. 踩坑记录（本仓库实际发生过）

1. **tag 大小写不匹配**：仓库原 tag 是 `FW-V0.5.6`（大写），而 `--match='*fw*'` 区分大小写匹配不到 → git describe 回退到短哈希 → 正则解析失败 → **每次 `make` 静默生成 0.0.0-dev 并覆盖 `autogen/version.c`**。已改名为小写 `fw-v0.5.6`。
2. **附注 tag 改名的坑**：`git tag fw-v0.5.6 FW-V0.5.6` 这种改名方式无效——附注 tag 对象内部嵌着创建时的旧名，`git describe` 取的是**对象内嵌名**而不是 ref 名，照样匹配失败（git 会警告 "tag ... is externally known as ..."）。正确做法：

   ```bash
   git tag -d FW-V0.5.6                       # 删旧 ref
   git tag -a fw-v0.5.6 -m "..." <commit>     # 指向同一 commit 重建,内嵌名正确
   ```

3. **根目录 `version.c` 是摆设**：仓库根曾有一份手工拷贝的 `version.c`，不在 Makefile 的 `C_SOURCES` 里，从不参与编译；真正生效的只有 `autogen/version.c`（每次构建重新生成）。该文件已删除。
4. **直接改 `autogen/version.c` 不生效**：AUTOHEADERS 每次 `make` 都重新生成它，手改会被覆盖。想改版本号只有一条路：改 git tag。
